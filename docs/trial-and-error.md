# 시행착오

추천과 검색을 만들면서 상수와 방향을 감으로 정하고 시작했다. 그런데 하나씩 재보니
열 번 넘게 틀렸다. 틀린 것과 그걸 어떻게 알았는지를 남긴다. 이 프로젝트에서 가장 값이
컸던 부분이다.

측정 방법은 하나로 통일했다. 시드 유저가 좋아한 기록의 20%를 가리고, 상위 10에서
몇 개를 되찾는지 본다. 같은 홀드아웃으로 인기순도 나란히 재서 비교 기준으로 삼는다.
`seed=42` 로 고정하고, `Recall@10`(되찾은 비율)과 `NDCG@10`(순위까지 반영) 두 지표를 본다.

## 가중치를 잘못 잡아 인기순보다 4.6배 나빴다

처음엔 내용 점수 0.7, 이웃 점수 0.3으로 시작했다. "시드가 적어 협업 신호가 얇다" 는
게 근거였다.

```
   내용:이웃   Recall@10   인기순
  0.7:0.3        0.021     0.097   ← 기존
  0.3:0.7        0.130     0.097
```

문제는 두 점수의 범위가 서로 달랐다는 데 있었다.

```
내용 점수   0.35 ~ 0.90   최소 유사도가 바닥이라 0 근처로 안 간다
이웃 점수   0.00 ~ 1.00   최댓값 정규화라 1등만 1.0
```

그러니 이런 일이 벌어진다.

```
줄거리만 비슷한 영화   0.7 × 0.85 + 0.3 × 0.00 = 0.595
사람들이 좋아한 영화   0.7 × 0.40 + 0.3 × 1.00 = 0.580   ← 진다
```

가중합이 두 신호를 섞은 게 아니라, 한쪽이 독식하고 있었던 것이다.

<br>

## 30% 를 줘도 자리가 안 생긴다

"10칸 중 3칸을 내용 점수에 준다" 는 안을 검토했다. 그런데 커버리지를 재보니 전제부터
깨져 있었다.

```
             서로 다른 영화   내용 점수만으로 뽑힌 것
0.7:0.3          132 편            75.5%
0.3:0.7           97 편             0.0%
```

내용 점수의 최대값(0.90 × 0.3 = 0.27)이 이웃 점수 10등조차 못 넘는다. 비중을 준다고
자리가 생기는 게 아니었다. 자리가 필요하면 자리를 떼는 수밖에 없고, 그래서 신작은 점수
경쟁이 아니라 별도 칸으로 넣기로 했다.

## 지표 하나로 판단하면 안 되는 사례

LLM 재랭킹이 순서를 낫게 하는지 쟀다.

```
           Recall@10   NDCG@10
재랭킹 전      0.120     0.216
재랭킹 후      0.120     0.218
```

증거가 없었다. "이유 문장만 받고 순서는 점수순으로 두자" 는 쪽으로 기울었는데,
커버리지를 재보고 생각이 뒤집혔다.

```
점수순   서로 다른 작품 67개   상위 10편 점유 44.8%
재랭킹   서로 다른 작품 85개   상위 10편 점유 32.6%

점수순 10위 밖에서 올라온 자리   225 / 500 (45%)
```

자리의 45%를 바꾸는데 정확도는 그대로였다. 점수 11~30위와 1~10위의 실제 품질 차이가
거의 없다는 뜻이다. 비용이 같으니 더 넓은 쪽을 쓴다. Recall 과 NDCG 만 봤다면 폐기했을
결정이었다.

<br>

## 트레이드오프가 없었던 유일한 변경

이웃을 겹친 개수로만 세면, 많이 본 사람이 모두의 이웃이 되어 버린다. 실제로 1,932편을
평가한 시드 하나가 거의 모든 유저의 이웃으로 잡히고 있었다. 그래서 겹침을 합집합으로 나눴다.

```
                 Recall   NDCG   서로 다른 작품   상위10 점유
개수 합계          0.126   0.249       63          50.5%
자카드            0.152   0.268       74          46.7%
```

지금까지 잰 것 중 정확도와 다양성이 함께 오른 건 이 변경뿐이다.

<br>

## 신작 칸 — 예상이 두 배 틀렸다

2018년 이후 영화는 시드 평점이 없어 이웃 점수가 0이다. 그래서 200칸 중 0칸이 나온다.
칸을 떼는 비용을 30%쯤으로 잡았는데, 막상 재보니 하위 칸은 원래 잘 안 맞아 손실이 작았다.

```
신작 칸   Recall   서로 다른 작품
   0칸    0.153        82
   2칸    0.130       101
   4칸    0.110       108
   6칸    0.091       101   ← 인기순 아래
```

2칸이면 커버리지가 23% 늘었다. 4칸부터는 커버리지는 안 늘고 정확도만 깎였다.

한 가지 더 배웠다. 최근 2년과 그 이전을 나눠서 뽑아야 한다. 한 풀에서 뽑으면 편수가 많은
옛날 것이 이긴다. 그리고 유사도 상위 20개에서 무작위로 고른다. 1등 0.658과 20등 0.630은
실질 차이가 없는데, 순서 하나로 갈려 모두가 1등만 받아 가고 있었기 때문이다.

## 추가했다가 뺀 것

국립중앙도서관 API 는 알라딘과 겹치는 정보만 주어 뺐다.

KOBIS 는 한국 영화를 채우려고 1년치 86편을 넣었다가 지웠다. 개봉 목록과 관객수만 줄 뿐
포스터·줄거리·평점이 없어 결국 TMDB 로 다시 찾아야 했는데, 그러면 KOBIS 가 하는 일은
"이 영화를 찾아봐라" 하나뿐이었다. 평점 있는 55편만 남기고 코드는 지웠다.

MovieLens 32M 은 아래에 따로 적는다.

## 데이터를 19배 넣고 얻은 것이 없다

시드가 610명이라 이웃이 얇다고 봤다. 그래서 3,200만 건짜리 데이터셋에서 유저를 뽑아
11,500명, 평점 100만 건을 넣어 봤다.

```
                        610명    11,500명
추천 / 인기순 배율        1.52      1.54
커버리지 (서비스 경로)     176편     165편
상위 10편 점유            43.4%     44.8%
후보 30 안의 신작          0건       0건
```

절대 Recall 은 0.125에서 0.145로 올랐지만 인기순도 0.082에서 0.094로 같이 올랐다.
평가 대상 200명이 다른 사람들로 바뀌었기 때문이다. 각 실행 안의 배율만 비교가 성립하는데,
그 배율은 거의 안 움직였다.

이유는 이렇다. 이웃이 1만 명이 되면 "이웃이 좋아한 것" 의 합이 결국 전체 인기순으로 수렴한다.

신작이 여전히 0건인 데는 또 다른 이유가 있었다. 평점은 붙지만 편당 11.9건뿐이다. 고전은
326.5건이다. 고전은 25년치가 쌓였고 신작은 5년치인 데다, 20만 유저 중 5.7%만 뽑느라
거기서 17배가 더 깎였다. 전량이면 편당 200건쯤 되겠지만 2,400만 행이라 무료 티어에 안 들어간다.

결국 `user_contents` 240MB 를 쓰고도 얻는 게 없어 접었다.

### 대조군을 먼저 안 쟀으면 반대 결론이 났다

새 시드는 평점 4.0 이상만 넣었는데 기존 시드는 전 평점을 갖고 있었다. 이 필터 하나만
걸어 보니 추천은 0.151에서 0.125로, 인기순은 0.097에서 0.082로 둘 다 15% 떨어졌다.
낮은 평점이 "이미 본 것" 으로 후보를 걸러 주고 있었던 것이다.

이걸 안 쟀다면 0.125를 0.151과 비교해서 "새 데이터가 나쁘다" 는 반대 결론을 냈을 것이다.

### 그리고 같은 실수를 그날 또 했다

위 필터가 커버리지를 137에서 176편으로 올린다고 적었다. 그런데 둘은 세션이 다른 숫자였다.
137은 지난 카탈로그에서 잰 값이고 176은 오늘 값이다. 같은 조건으로 다시 재니 오히려 반대였다.

```
              서로 다른 작품   상위10 점유
전 평점            199편         37.2%
4.0 이상만         176편         43.4%
```

게다가 이 변경은 애초에 제품에 닿지도 않는다. 이웃 판정·자카드 분모·인기순·취향 중심이
전부 4.0 이상만 보므로, 시드의 낮은 평점을 지워도 실사용자 추천은 한 글자도 안 바뀐다.
커버리지가 움직인 건 평가 대상 본인의 낮은 평점이 지워져, 싫다고 한 영화가 후보로 돌아온
탓이었다. 대조군을 재서 결론 하나를 구해 놓고, 바로 다음 문단에서 대조군 없이 또 적은 셈이다.

## 커버리지 — 세 번 실패하고 네 번째에 풀었다

카탈로그 4,894편 중 추천에 나오는 건 199편(4%)뿐이었다. 200명에게 거의 같은 목록을 주고
있었다. 넓혀 보려 세 가지를 시도했지만 전부 같은 벽에 부딪혔다.

```
가중치 조정    0.85까지 아무 일 없다가 1:1에서 절벽. 조절 불가
RRF (순위 결합)  눈금 문제인 줄 알았는데 가중치 문제였다
자리 떼기       조절은 되는데 3칸 줘도 129편(2.6%). 정확도만 깎임
```

셋 다 "후보를 더 넣자" 는 발상이었다. 정작 통한 건 넣는 게 아니라 점수 계산을 고친 것이었다.

한 유저의 이웃 점수 상위 100을 좋아요 수와 나란히 놓아 봤다.

```
순위    점수    좋아요   제목
  1    1.000    274    쇼생크 탈출
 10    0.558    118    12 몽키즈
100    0.246     44    엑스맨 2

점수 순서와 인기 순서가 83.5% 일치
```

이웃 점수가 사실상 인기순이었다. `signal = Σ 자카드 가중치` 라 그 작품을 좋아한 이웃이
많을수록 커진다. 모두가 좋아하는 작품은 내 취향을 알려주지 않는다. 남들이 잘 안 보는
작품을 나와 겹쳐 좋아한다는 것, 그게 신호다. 그래서 좋아요 수로 나눴다.

```
              나누기 전   나눈 뒤
Recall@10      0.149      0.190
커버리지        199편      460편
상위 10편 점유   37.2%      14.6%
```

정확도와 커버리지가 함께 올랐다. 자카드에 이은 두 번째, 트레이드오프 없는 변경이다.

이어서 주변 상수를 다시 재보니 내용 점수가 영화에서는 오히려 해로웠다. 나눈 뒤에도 한 편도
못 올리면서 순서만 흔들어 정확도를 깎고 있었다. 그래서 0으로 내렸다. 책은 이웃 점수가
없으니 그대로 뒀다.

## 5편이면 인기순을 앞선다는 근거가 무효였다

새로 가입해 보니 추천이 안 열렸다. 기록 다섯 편을 채워야 열리는데, 그게 "평점 4.0 이상
다섯 편" 이라 생각보다 멀었다. 화면은 "5편을 평가하면" 이라고만 적어 두어, 3점을 다섯 개
준 사람은 막대가 0/5 에 멈춘 이유를 알 수 없었다.

기준을 낮추기 전에 재봤다. 기록 많은 시드에게서 N편만 남기고 나머지를 가려 신규 가입자를
흉내 냈다. 정답은 네 건으로 고정하고 400명 평균을 봤다.

```
기록      4.0     3.0
 3편     0.31    0.50
 5편     0.46    0.83
 7편     0.74    1.06
10편     1.19    1.26      인기순 대비 배율
```

두 가지가 드러났다. 하나는 4.0 기준에서 다섯 편이 인기순의 0.46배라는 것이다. README 에
적어 둔 "5편부터 앞선다" 는 커버리지를 고치기 전에 잰 값이었고, 점수 계산을 바꾼 뒤로
이미 무효였다. 앞서는 지점은 열 편으로 밀려 있었다.

다른 하나는 3.0 이 모든 구간에서 낫다는 것이다. 신호가 43,425건에서 71,696건으로 늘어
적은 기록으로도 이웃을 찾는다. 앞서는 지점이 열 편에서 일곱 편으로 당겨졌다.

전체 지표로 보면 3.0 은 손해다. Recall 이 0.190에서 0.173으로, 커버리지가 494편에서
438편으로 내린다. 다만 이 Recall 은 정답 정의가 함께 넓어져 곧바로 견줄 수 없고,
인기순 대비 배율은 1.94와 1.97로 같다. 그래서 커버리지 11% 를 내주고 진입 구간을 샀다.

`LIKED_RATING` 은 3.0 으로 내렸다. 추천을 여는 편수는 앞서는 지점인 7로 올릴까 하다가
5에 뒀다.

한 장르만 5편 넣어 무엇이 나오는지 봤더니, 열 자리 중 다섯이 전체 인기순과 겹쳤다.
스릴러만 다섯 편 담았는데 쇼생크 탈출과 포레스트 검프가 왔다. 기록이 적으면 겹침 두 편
조건에 걸리는 사람이 너무 많아, 이웃의 합이 결국 인기순이 되는 것이다.

그래서 이웃 조건을 3, 4로 올려 봤다.

```
겹침   Recall   장르 일치(스릴러 5편)
 2      0.173      3/10
 3      0.177      2/10
 4      0.167      1/10
```

개인화는 안 늘고 전체 지표만 갈렸다. 겹침을 올려도 이웃이 좁아지는 만큼 후보가 얕아져
상쇄되는 듯하다. 근본은 기록 수라 조건으로 덮을 수 없었다.

막을 수 없으니 알리기로 했다. 추천은 5편부터 열되, 기록이 열 편 아래면 화면이
"기록이 적어 인기작이 섞인다" 고 적는다. 못 이기는 구간을 감추는 것보다 어디쯤인지
말하는 편이 낫다고 봤다.

상수 하나를 고치면 그 상수를 근거로 삼은 문장도 다시 재야 한다. 커버리지를 고칠 때
이 곡선을 같이 재지 않아, 틀린 근거가 README 에 그대로 남아 있었다.

## 지표가 작업과 안 맞을 때 — 검색

자연어 검색을 붙이면서, 처음으로 정량 지표를 최종 판단으로 쓰지 않은 사례가 나왔다.

작품마다 사용자가 칠 법한 질의를 LLM 으로 만들어 Recall 을 쟀다. 문제는 정답이 하나뿐이라는
점이었다.

```
"가족 우주 영화" → 애드 아스트라 1등
```

애드 아스트라가 틀린 답은 아니다. 그런데 정답을 인터스텔라로 잡으면 0점이 된다. 검색은
여러 개 중 쓸 만한 걸 주면 되는데, 평가는 하나만 정답으로 둔다. 내가 좋아할 걸 맞히는
추천과는 성격이 다른 것이다.

색인을 분위기 문장으로 바꾸니 R@10 은 거의 안 올랐지만("긴장감 스릴러" 에 액션·재난 대신
실제 스릴러가 나오는 식으로) 결과는 눈에 띄게 나아졌다. 지표가 작업에 안 맞으면 정성으로
판단한다.

<br>

## 정답이 없는 것을 어떻게 쟀나 — 도서

영화 쪽을 손보다 알았다. 도서 추천은 6단계에서 다 만들어 놓고 한 번도 들여다본 적이 없었다.

```sql
select c.type, count(*) from user_contents uc join contents c on c.id = uc.content_id group by 1;
-- MOVIE  86,666
-- (BOOK 행 없음)
```

시드가 MovieLens 라 도서 평점이 0건이다. 홀드아웃 평가에는 정답이 필요한데 만들 수가 없다.
공개 데이터셋도 안 맞았다 — Book-Crossing 은 2004년 영미권이고 Goodreads 도 한국 도서가
거의 없다. 카탈로그가 한국 베스트셀러 708권이라 겹치는 것이 없다.

정확도를 못 재면 아무것도 못 재는 것은 아니다. **무엇이 나가는지는 잴 수 있다.** 책은
이웃 점수가 전부 0이라 내용 점수 하나로 도니 결정적이고 들여다볼 수 있다.

가상 사용자를 만들었다. 시드 유저를 빌려 트랜잭션 안에서 도서 평점을 붙였다 되돌린다.
처음엔 100명에게 무작위로 다섯 권씩 좋아하게 했다.

```
서로 다른 책      284권 / 708권 (40.1%)
상위 10권 점유    17.4%
평균 유사도       0.531
```

커버리지가 영화(9.4%)보다 훨씬 넓다. 내용 점수가 이웃 점수보다 넓게 퍼지기 때문이다.
눈으로도 봤다. 헤르만 헤세 시집에서 나르치스와 골드문트를, 그리스 로마 신화에서
오디세이아를 찾아 왔다. 뒤죽박죽인 입력에서 지배적인 갈래를 잡는다.

그런데 `픽션들` 이 100명 중 26명에게 갔다. 무슨 취향이든 이 책으로 빨려드나 싶었다.

### 실험 설계가 틀렸다

가상 사용자가 비현실적이었다. 무작위로 다섯 권을 뽑으니 이유식과 카뮈와 드라큘라를 같이
좋아하는 사람이 됐다. 실제 사용자는 취향이 일관돼 취향 중심이 뾰족하다.

장르 7개에 각 15명, 같은 장르에서만 다섯 권씩 좋아하게 다시 만들었다.

```
              무작위 취향   일관된 취향
서로 다른 책      284권       248권
상위 10권 점유    17.4%       20.8%
평균 유사도       0.531       0.574
```

```
인문학       번역의 철학(11), 사피엔스(9), 영웅의 귀환 오뒷세이아(8)
어린이       흔한남매의 흔한 호기심(10), 흔한남매 이무기(9)
경제경영      자본주의 시대에서 살아남기(15), 인생을 바꾸는 투자학개론(14)
자기계발      렛뎀 이론(12), 어떻게 살아낼 것인가(11)
```

일곱 장르가 서로 다른 책을 받고 각 장르 안에서 말이 된다. 평균 유사도도 0.531 에서
0.574 로 올랐다.

**그리고 `픽션들` 이 사라졌다.** 상위 3위 안에 한 번도 안 나온다. 그게 아니라 취향 중심이
흐릴 때 나오는 기본값이었다. 실제 사용자에게는 생기지 않을 문제를, 내가 만든 가짜 입력이
만들어 낸 것이다.

정확도는 여전히 미지수다. "장르가 갈린다" 와 "좋은 추천이다" 는 다른 얘기고 후자를 판정할
데이터가 없다. 그래도 잴 수 있는 것과 없는 것을 갈라 놓으니, 못 재는 것 하나로 전부를
모른다고 적을 이유는 없어졌다.

## 실수한 것

배포가 통째로 죽은 적이 있다. 재시도 라이브러리가 수집 전용 의존성 그룹에 있었는데,
스크립트만 쓰던 코드가 재랭킹을 거치며 런타임 의존이 됐고, 배포 환경에는 그 그룹이 안 깔린다.
로컬 테스트 133개가 전부 통과한 채로 배포만 죽었다.

```bash
uv run --no-dev --no-group etl python -c "from app.main import app"
```

전송량 한도를 넘겨 18일을 멈춘 적도 있다. 평가를 프로덕션 DB 에 대고 열 번 넘게 돌린 탓이다.
저장 용량만 계산하고 있었는데, 정작 먼저 막힌 건 전송량이었다.

```
저장   0.12 / 0.5 GB
전송   6.48 / 5 GB    ← 여기서 막혔다
```

원인은 취향 중심을 만들 때 임베딩을 파이썬으로 끌어와 평균을 낸 것이었다. 유저당 1536차원
벡터 수십 개, 평가 한 번에 수백 MB. 이걸 Postgres 집계로 내려 결과 벡터 하나만 받게 고쳤고,
지표는 그대로였다. 평가용 로컬 DB 를 세우고, 평가 스크립트가 원격을 향하면 연결 전에 멈추게
했다. 막을 수 없는 실수를 싸게 실패하도록 바꾼 것이다.

(장애 대응의 자세한 과정은 [문제 해결](problem-solving.md) 에 있다.)

## 배운 점

상수에는 근거가 아니라 측정값을 적는다. 계획서에 "이유는 있고 측정은 안 됐다" 를 구분해
적기 시작한 뒤로 뒤집히는 횟수가 줄었다.

지표 하나로 결정하지 않는다. 재랭킹은 정확도만 봤으면 버렸을 것이다.

반복해서 돌리는 스크립트는 로컬부터 세운다. 프로덕션에 대고 실험하면 언젠가 한도를 넘는다.

LLM 에 개수 제약을 맡기지 않는다. 판본 중복, 시리즈, 인용 횟수 — 세 번 다 절반만 지켰다.
반드시 지켜야 하는 것은 코드로 옮긴다.

작은 표본이 전체를 오도한다. 질의 확장은 한 영화가 3위로 살아난 것을, 색인 개선은 600편
실험의 +30%를, 4.0 필터는 세션이 다른 두 숫자를 보고 채택할 뻔했다. 전부 전체로 다시 재서
갈렸다. 실험 표본이 작으면 결론도 작게 믿는다.

막힌 곳을 넓히기 전에 어디가 막혔는지부터 잰다. 커버리지는 세 번 "후보를 더 넣자" 로
실패했다. 단계별로 세어 보고서야 병목이 후보 수가 아니라 점수 계산이라는 걸 알았다.
방법을 꺼내기 전에 원인을 잰다.
